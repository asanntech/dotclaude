# Evidence Video（証跡動画の録画）

## 引数

`/evidence-video <ラベル> [出力先]`

- **ラベル**: `before` / `after` など。動画は `<出力先>/<ラベル>.mp4` に保存される。省略されたら確認する
- **出力先**: 省略したら、コマンドを実行したディレクトリ（`pwd`）を使う

## 録画の方式（この方式を守る）

MCP のツールで1手ずつ操作しながら録画すると、Claude が考えている間の止まった画面がそのまま動画に残る。
そこで次の2段階に分ける。

1. **下見**: MCP のツール（`browser_navigate` / `browser_snapshot` / `browser_click` など）で実際に操作して、
   手順とロケータを確かめる。下見の間は録画しない
2. **一括再生**: 確かめた手順を Playwright のシナリオ（`scenario.js`）に書き、`browser_run_code_unsafe` で1回で流す。
   録画するのはこのときだけ

## 手順

### 1. 準備

- 出力先を絶対パスにして `mkdir -p` する
- `command -v ffmpeg` で ffmpeg があるか確かめる。無ければ `brew install ffmpeg` してよいかユーザーに確認する

### 2. 既存のシナリオを確認する

`<出力先>/scenario.js` があれば、before で使ったシナリオなので**そのまま再利用する**。
`LABEL` の定数だけを今回のラベルに書き換えて、手順4へ進む（下見はしない）。
before と after で流す手順が違うと比較にならないので、手順は書き換えない。
修正によって画面の文言やロケータが変わり、どうしても流せない場合は、変える箇所をユーザーに示して了承を得る。

### 3. 下見してシナリオを書く

1. 次の3点を確認する。会話や PR の内容からわかる場合は聞かない
   - 対象の URL（ローカルの開発サーバーなど）
   - 動画で見せたい点（何を操作して、何が起きれば修正できたとわかるか）
   - ログインが必要か。必要なら、下見の最初にログインしておく（ログイン状態は録画用のコンテキストに引き継がれる）
2. MCP のツールで最初から最後まで操作する。各要素について安定したロケータを確かめる。
   優先順位は `getByRole` → `getByLabel` → `getByText` → `getByTestId` で、CSS セレクタは最後の手段にする
3. このスキルの `references/scenario-template.js` を `<出力先>/scenario.js` に複製し、2か所を書き換える
   - **設定**: `OUT_DIR`（絶対パス）、`LABEL`、`BASE_URL`
   - **手順**: `click` / `fill` / `select` / `result` のヘルパーで書く。特殊な操作は `step(テロップ, async () => {...})` で書く

テロップの書き方:
- 1手順に1行。番号を付けて、何をするかを短く書く（例: `① 検索欄に「foo」と入力`）
- 最後は必ず `result('結果: 〜', ...)` にして、修正の効果が見える要素を示す
- before と after で同じ文言を使う。期待する結果ではなく、確かめる観点を書く（例: `結果: 送信後のメッセージを確認`）

### 4. 一括再生で録画する

`scenario.js` を Read し、その中身をそのまま `browser_run_code_unsafe` の `code` に渡して実行する。
`filename` は使わない。MCP がプロジェクト内のファイルしか読ませないので、出力先がプロジェクトの外だと失敗する。
成功すると `{ raw, trimStart }` が返る。

失敗したら、エラーの内容からロケータや待ち方を直して流し直す。
**3回続けて失敗したら止めて**、失敗した手順とエラーをユーザーに報告する。
途中までの動画は `.raw/<ラベル>-failed.webm` に残るので、原因を調べるのに使える。

### 5. mp4 に変換する

```bash
<このスキルのディレクトリ>/scripts/to-mp4.sh <raw> <出力先>/<ラベル>.mp4 <trimStart>
```

10MB を超えたら、スクリプトが画質を落として再変換する。変換に成功したら `<出力先>/.raw` を消す。

### 6. 報告する

- 動画のパス、長さ、サイズを報告する（スクリプトの出力をそのまま使う）
- before のときは、続けて次のことを案内する: 「アプリを修正後の状態にしてから `/evidence-video after <同じ出力先>` を実行してください。同じシナリオで録画します」
- after のときは、before と after の2本のパスを並べて示す

## 品質の基準

シナリオを書き終えたら、流す前に次の点を確かめる。

- [ ] 固定の待機（`waitForTimeout`）を手順の中に書いていない。待つのは `locator.waitFor()` / `p.waitForURL()` など、条件が満たされるまでの待機だけ
- [ ] 止まる時間は、テロップを読ませる時間（`HOLD`、約1.2秒）と最後の結果表示（`RESULT_HOLD`、約2秒）だけ
- [ ] 操作はすべてヘルパー経由で行い、操作する前に対象を枠線で強調している
- [ ] すべての手順にテロップがあり、最後が `結果: 〜` になっている
- [ ] 見せたい点に関係しない操作（設定画面に寄り道するなど）を入れていない
- [ ] 解像度は 1280x720。音声は入れない

## やってはいけないこと

- MCP のツールで操作しながら録画する（思考時間が静止区間として残る）
- 録画や変換に失敗したのに、成功したように報告する
- before と after で別の手順を流す
- ユーザー自身のアプリ以外のサイトを録画する
- パスワードなどの秘密情報を `scenario.js` に書く（ログインは下見の中で行い、その状態を引き継ぐ。値は画面にも動画にも残るので、テスト用のアカウントを使ってもらう）
